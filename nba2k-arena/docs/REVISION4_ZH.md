# Revision 4：近景结构与地形缺口修订

这是独立的待游戏验收候选，基于已发布的 Revision 3 原生 IFF（SHA-256 `9bdb9f341d40cbdc22d0285ce456fca8234ee32bec1854011213ea78c9f5cc99`）。原 donor、R3 分发包和历史候选均保留。状态与本轮实际产物哈希见 [validation.json](../output/revision4/validation.json)。

[下载完整候选包](../output/revision4/venice_court_revision4.zip)。它包含两个同编号 IFF、校验报告和说明；外层 ZIP 无损压缩，内部原生 IFF 仍使用 ZIP_STORED。准备脚本不安装 MOD、不启动游戏，也不安装建模软件。

## 本轮具体修订

五张原图作为同一个球场的多视角证据，忽略人物。[AI 增强图](../textures/source/references/enhanced/README.md)用于辅助查看，新增的微小细节不作为真实测量。原图均为 640×480，增强图实际为 1448×1086。

- **双弯臂路灯。** 原图 01 右缘、02 棕榈之间及 03 右侧共同可见。增加三组银灰色弯臂和向下的多层灯罩，带底座、连接套与小型检修板。杆高、灯罩尺寸和具体摆位为设计参数；仅增加日间几何，没有虚构夜间发光行为。
- **桶组。** 原图 04 的近景是开口绿色桶、外翻灰白塑料内衬及旁边灰色圆顶构件。补桶壁、内壁、暗底、口沿和内衬折叠；圆顶改为混凝土质感。此前第三组放在草台侧缘、底部可能埋入，移至相邻铺地，避免穿插。
- **金属看台。** 保留低矮五排设计、原朝向和位置，补落地横脚及交叉支撑。排数、紧固件和局部尺寸并非照片精确测量值。
- **草台端部和缺地。** 将长直盒体端部改为平滑回转，保持三个低台阶及植物接地。旧模型在 `x=1100..2435 cm`、`|z|=5050..6500 cm` 留有无地面的缺口，预览中露出浅蓝背景；本轮补成连续地面，不把缺面当成海景。

所有原有贴图像素与分辨率保持，新增道具使用独立材质/纹理。R3 的比赛地面、标线、棕榈、天空参数和地板光照方案不在本轮改动范围。

几何检查图：[桶组](../build/revision4/props/revision4_bins_preview.png)、[看台](../build/revision4/props/revision4_bleachers_preview.png)、[草台](../build/revision4/terraces/terraces_exported.png)。这些由导出几何作独立投影/近似光照检查，不是游戏截图；草台立视图高度专门放大 8 倍便于检查低台阶。桶内衬保留真实褶皱，周向 256 段并使用连续法线，已消除逐三角形硬明暗。看台支架与座板使用一致的浅色金属材质。

## 修改边界与可复现性

[构建脚本](../scripts/build_revision4.py)先验证已发布 R3 的完整 SHA-256，再制作新文件。相对于 R3，唯一改写的现有归档条目是 `level.SCNE`；其他已有条目逐字节核对。新增几何与道具纹理写入新资源名，不能覆盖既有二进制。

场景内只允许替换三个先前生成的装饰模型：`venice_v3:bins`、`venice_v3:bleachers`、`venice_v3:grass_terraces`，并增加路灯。唯一调整的既有生成 Object 是 `venice_v3:bins_2`，仅 x 从 1110 移至 940 cm，其余矩阵分量和属性保持。任何原 donor Object、原篮架、权重/骨骼、碰撞、玩法锚点均不因此改动。

```sh
python3 nba2k-arena/scripts/build_revision4.py
python3 -m unittest discover -s nba2k-arena/tests -v
python3 nba2k-arena/scripts/revision4_preview.py --three-dir /path/to/existing/three
```

需要既有 Python、NumPy、Pillow；预览使用既有 Three.js。脚本不会自动安装它们。新 checkout 可以直接从仓库携带的 R3 分发 ZIP 读取并核验构建输入。

本轮最终 Python 测试 **109 项通过**，记录见 [revision4_tests.txt](revision4_tests.txt)。覆盖原生索引/顶点与材质资源、原文件保护、接地和缺地覆盖，以及桶内衬平滑法线/口沿不相交。构建另核验原生 IFF 与外层分发 ZIP 的 CRC 和解包后 SHA-256；这些检查不包含 Windows 导出器执行或游戏运行。

## 仍未通过游戏验收的事项

**原生运行时效果没有被静态测试或 WebGL 预览证明。** 本地预览直接解码最终 IFF 的几何、实例矩阵及颜色贴图，但使用中性近似光照，不能冒充 NBA 2K 截图。游戏曝光、天空、树木颜色、真实日影、反射和表现一致性仍需在同一候选下检查。

[原 shader 审计](revision4_shader_audit.md)确认所用 Default PS 包含逐灯光照和 IBL。它依赖引擎的全局光照资源；现有证据不能保证新静态对象一定进入 Default-only 路径，也不能证明投射的树影已进入接收端可见度。因此没有用猜测的 mask 或 GBuffer 别名“修复”这些未知项。

[篮架审计](revision4_basket_audit.md)已解码原玻璃及反射专用篮圈，保留真实绑定边界。主篮架仍缺四个外部顶点/索引资源。本轮**尚未把 donor 的室内篮架、计时器和底座换成照片里的细金属支柱**；反射辅助几何也没有伪装成实体篮圈。原篮架在游戏仍依靠其原资源，预览明确显示缺失资源边界框。

补齐准确资源、验证几何和全部 LOD 后，才能在保持实体篮圈、篮板与篮网锚点的条件下替换室内支架外观。原底座碰撞若保持字节不变，也不会自动变为细支柱碰撞，后场通行仍需实际检查。

已准备 [Windows 手动只读导出器](../tools/README.md)，供读取用户本地游戏 manifest 中这四条精确资源，无需另装工具。它校验解码尺寸和 CRC，只导出到新目录，不启动游戏或复制 DLL。当前 Mac 环境不能运行 Windows/Oodle 路径，脚本尚未经过 Windows 执行及 C# 编译验证，不能把准备完成当成导出成功。

动态观众模式同样没有运行证据。当前候选不能据此标为最终完成或“每个细节已通过”。

下一轮照片对应项：原图 02 的中场明确有浅灰实心圆盘，01 的场地左缘也支持这一填充；当前保留的 R3 中圈仍是标准双白圈，没有这块浅灰填充。原图 03 的罚球区及圆弧内也可见明暗分区，应在保持比赛尺寸、原地面 UV 和正确绘制层级的条件下单独处理。远处低楼周边广场、雕塑轮廓和局部磨损仍有继续核对空间。
