# R6 海岸连续性审计（R5 实物基线）

R5 存在真实远景地面缺面。大片缺口来自步道、沙坡和草地的结束位置不一致；近岸厘米级接缝来自整片海面与陆地共享过大的位置量化范围。两者需要分别修复，不能归结为颜色、天空贴图或倒置法线。

## 来源与方法

- 候选提交：`2ca8f1e`。
- 读取本地 `output/revision5/venice_court_revision5.zip` 内的 `arena_700_int.iff`，SHA-256 已实算匹配：`2fd02c8cfb3d771947cd4fe655db1f64f1ecf51a598bc1a8656ba16e1a670a3d`。
- 直接读取该 IFF 的 `level.SCNE`、POSITION 缓冲、R16 索引及实际 Object Matrix，解析所有 Prim；没有从照片或模型声明的包围盒反推顶点。
- 审计地形为 `venice_v3:coast`、`venice_v3:grass_terraces`、`venice_v3:promenade` 及完整原生主 floor。三个生成地形 Object 的 Matrix 均为单位变换，因此下表为实际世界坐标，单位 **cm**。
- 原生顶点、各 Prim、42 个垂直覆盖点、6 条地形视线、1375 个近景回归点保存在 `build/revision6/coast_audit.json`。审计没有修改模型或运行游戏。
- 视线以地形双面求交，避免把背面剔除误称为缺面。它证明地形缺失，不声称穿透树木/道具后每一像素都可见，也不等同于游戏实测机位。

## 大缺口：结束位置不一致

`scripts/revision3_landscape.py` 的生成范围本来就是：步道 `|z|≤10000`，沙坡 `|z|≤20000`，远草/背沙 `|z|≤25000`，海面 `|z|≤160000`。原生量化后的缺面如下，正负两端均存在。

| 区域 | 实际 x 范围 | 实际 \|z\| 范围 | 证据与面积 |
|---|---:|---:|---|
| 步道终点之后 | 4098.229953…4498.626688 | 9997.711147…24997.940032 | 两端总缺面约 1201.21 m²；(4300, ±15000)、(4300, ±24000) 垂直无地面 |
| 沙坡终点之后 | 4498.626688…8497.711147 | 19997.863737…24997.940032 | 两端总缺面约 3999.15 m²；(6500, ±22500) 垂直无地面 |
| 全部陆地裸端之后 | −24998.893721…8497.711147 | 24997.940032…160000 | 陆地已结束，只有 x≥8497.711147 仍有海面；(3000/4300/6500, ±30000) 均无地面 |

原生海岸 16 个三角形都朝上且非退化；上述空区不是三角形翻面。源码中缺少对应平面，实际缓冲也不存在覆盖面。

使用预览主机位 `[0,850,2200]`，下列地形射线在 80000 cm 范围内没有任何双面交点：

| 视线瞄准世界点 | 结果 |
|---|---|
| `[4300,98,-15000]` | 穿过缺失步道带，无地形命中 |
| `[6500,30,-22500]` | 穿过缺失沙坡带，无地形命中 |
| `[3000,98,-30000]` | 越过完整陆地裸端，无地形命中 |
| `[4300,98,-9000]` | 对照命中现有步道，y=98.068975 |
| `[6500,30,-19000]` | 对照命中现有沙坡 |
| `[9000,-33.768975,-30000]` | 对照命中海面 |

这与远方蓝色楔形空区相符。只把步道或沙坡延长到 25000 会补两处内部缺面，却仍保留主机位可见的陆地裸端。

## 小接缝：不同量化网格

海岸模型 POSITION 为 `R16G16B16A16_UNORM`，`Scale=[320000,320000,320000,1]`，`Offset=[-97500,-159967.85,-160000,0]`。海面的 320000 cm 纵向跨度使 **全部 XYZ** 的量化步长达到 `320000/65535 = 4.882887 cm`。R4 草台为 `16000/65535 = 0.244144 cm`；promenade 为 `13000/65535 = 0.198367 cm`。

| 连接位置 | 原生实物结果 | 判断 |
|---|---|---|
| 草台—远草，\|z\|≈8000 | 草台止于8000；远草始于8000.610361；顶高100.365808→98.068975 | 0.610361 cm 草面断带及2.296834 cm高差；断带下方仍有y=0.411234的背沙，不是完全无底面 |
| 草台—步道，x≈4100 | 草台至4099.900816，步道从4098.229953起 | 有1.670863 cm平面重叠及约2 cm高差；并非4 m宽的大缺口 |
| 步道—沙坡，x≈4500 | 双方边界均4498.626688、y=98.068975 | 共享位置，无开缝 |
| 沙坡—海面，x≈8500 | 双方边界均8497.711147、y=−33.768975 | 共享位置，无开缝；必须保留完整连接 |
| promenade—草台，x≈1100 | 前者至1100.080110；后者始于1100.099184 | 0.019074 cm细缝；(1100.09, ±5500) 垂直无地面 |
| promenade—外沙，\|z\|≈6500 | 前者止于6500；外沙始于6501.564050 | 1.564050 cm细缝；(−3000, ±6500.5) 垂直无地面 |

R4 已修复的圆弧草台内部仍正常：x=1101…4099、z=−7999…7999 的1375个点全部有地形，包含旧空区 x1100…2435、\|z\|5050…6500。R6 不应重建这些草台或移动其植物、路灯。

## 格式约束与最小完整修复

R5 全部 SCNE 没有 POSITION 前三轴 Scale 不同的实例。已解码的原生 `VS.3e4e8775aa14fa50.shader`（临时 IR `default_vs.ll`）用同一标量 `%91=Scale/65535` 解码三个位置分量，再分别加 XYZ offset。不能仅因 SCNE 写着四元素数组就推断此 CLOD 路径支持每轴独立缩放。

最小可靠修复范围：

1. 保留所有原有 Object/Matrix、草台、promenade、主场地、材质和游戏字段。只替换生成 `venice_v3:coast` 的绘制内容，新增必要的 `venice_v3:coast_r6_…` 分块 Model/Object。
2. 分离原有海面与陆地。海面可保留原生两三角及其位置；近岸沿用已验证 exporter，在 R6 局部封装统一的 **16000 cm 草台网格**，通过整网格平移分块，避免修改历史 exporter 或 shader。
3. 填完整步道/沙坡中断区，并将陆地连续接到已有海面相同的远端包络；不能仅把裸端推到25000。使用少量简单分块平面，保持原有草、混凝土、沙材质，不增加海浪或造景。
4. 草台连接使用实际缓冲的边界和高度。promenade 的不同网格细缝可由新增海岸窄条在实物边界下方少量托接；避免与已有顶面共面，保持旧模型和对象字节不变。
5. 对最终新 buffer 再解码，重新执行上述空区点与视线、1375个近景点、全部交界的密集覆盖/高度采样，并检查法线、非退化、索引范围和旧 Object 一致性。

这里只确认几何原因和修复边界。游戏中的地形观感、材质、远景裁剪和天空颜色仍需实际运行确认。
